# MathBinder Lesson Standard

This document defines the official publishing standard for every production lesson in MathBinder. It is intended to ensure that lesson content is clear, accurate, consistent, accessible, reusable, and ready for future publishing platforms.

## 1. Lesson Identity

Every production lesson must include the following identity fields:

- lesson_id: A unique identifier for the lesson.
- title: The public lesson title.
- version: The lesson version number.
- author: The lesson creator or content author.
- review status: The current review state, such as Draft, Review, Approved, or Published.
- publication status: The publishing state of the lesson, such as Draft, Scheduled, or Published.

These fields establish the lesson as a distinct, trackable instructional asset.

## 2. Educational Metadata

Every production lesson should include educational metadata that helps teachers, parents, and students understand the lesson quickly.

Required metadata includes:

- grade band: The intended grade range.
- estimated completion time: A realistic expected time for student work.
- prerequisites: Prior knowledge or skills needed before beginning the lesson.
- learning objectives: Clear outcomes students should achieve.
- California Common Core standards: Relevant standards aligned to the lesson.
- keywords: Search terms that support discovery and organization.

This metadata should be concise, accurate, and useful for instructional planning.

## 3. Required Lesson Sections

Every production lesson must contain the following sections with a clear instructional purpose:

- overview: Introduces the lesson topic, purpose, and student focus.
- teach_it: Presents the core instruction, examples, and conceptual explanation.
- at_a_glance: Summarizes the main ideas in a compact form.
- common_questions: Addresses likely student questions and misconceptions.
- watch_it: Provides a video resource or explains that a verified resource is pending.
- practice_it: Gives students opportunities to apply what they learned.
- my_math_notes: Encourages learners to record key ideas, strategies, and reminders.
- real_life_math: Connects the topic to practical, everyday experiences.
- did_you_know: Adds an enriching or curiosity-building mathematical insight.

These sections should be present in a consistent structure so lessons feel familiar and dependable.

## 4. Quality Standards

Production lessons must meet minimum quality expectations in all major instructional areas.

- Worked examples: Each lesson should include clear, complete examples that model the method step by step.
- Practice questions: Lessons should include enough practice to build confidence and reinforce learning.
- Answer accuracy: All solutions, explanations, and examples must be mathematically correct.
- Misconceptions: Common errors should be identified and corrected clearly.
- Accessibility: Content must be readable and usable for a wide range of learners.
- Plain language: Explanations should be direct, clear, and understandable.
- Intervention support: Lessons should support students who need extra help, review, or alternative explanations.

Quality standards apply to both content and presentation.

## 5. Resource Standards

Lessons must follow resource rules for all supporting materials.

- Videos: Videos should be accurate, age-appropriate, and relevant. If a resource is not yet verified, the lesson should clearly indicate that it is pending.
- Images: Images should support learning and should not introduce confusion or visual clutter.
- External links: External links should be relevant, trustworthy, and appropriate for the audience.
- Placeholders: Placeholders should be temporary and clearly marked. Production lessons should not rely on vague or unfinished content.
- Copyright: All resources must respect copyright and usage rights.

Any resource used in a production lesson should be reviewed for accuracy, usefulness, and appropriateness.

## 6. Publication Checklist

Before publication, every lesson must satisfy the following checklist:

- [ ] The lesson has a unique lesson_id.
- [ ] The title, version, author, and metadata are complete.
- [ ] All required lesson sections are present.
- [ ] The lesson uses clear, accurate, and age-appropriate language.
- [ ] Worked examples and practice questions are included.
- [ ] Solutions and explanations are mathematically accurate.
- [ ] Common misconceptions are addressed appropriately.
- [ ] Accessibility expectations have been considered.
- [ ] All resources are reviewed, relevant, and properly attributed.
- [ ] The lesson is free of rendering logic and presentation code.
- [ ] The lesson is ready for review and publication.

Publication should not occur until the checklist is complete.

## 7. Future Metadata

The following metadata may be added later as the standard evolves:

- lesson difficulty
- reading level
- mastery checklist
- standards coverage
- review history

These additions can improve search, assessment, reporting, and long-term lesson management.

## 8. Lesson Flow

The recommended instructional sequence for a lesson is:

Overview
→ Teach It
→ At a Glance
→ Common Questions
→ Watch It
→ Practice It
→ My Math Notes
→ Real-Life Math
→ Did You Know?
→ Mastery Check (future)

This order is used because it moves from introduction to explanation, then to support, practice, reflection, and extension. The sequence helps students first understand the lesson, then review key ideas, then apply them with support and guidance.

## 9. Accessibility Standards

Production lessons should be designed to support broad learner access and readability.

Expected practices include:

- plain language: Use clear wording and avoid unnecessary complexity.
- readable formatting: Keep paragraphs, lists, and examples easy to scan.
- descriptive headings: Use headings that clearly describe the content that follows.
- color independence: Do not rely on color alone to communicate meaning.
- image alt text (future): Add descriptive alt text when images are used.
- keyboard accessibility (future): Ensure future interactive content can be used without a mouse.
- screen reader compatibility (future): Structure content so it remains understandable with assistive technologies.

Accessibility is a publishing expectation, not an optional enhancement.

## 10. Mathematical Accuracy Standards

Every lesson must meet rigorous mathematical accuracy standards.

Required expectations include:

- use mathematically correct terminology
- show all worked solutions accurately
- distinguish definitions from procedures
- identify common misconceptions correctly
- be reviewed before publication

Mathematical correctness is essential for trust, student learning, and long-term reuse of lesson content.

## 11. Assessment Expectations

Each production lesson should eventually include a balanced assessment structure.

Expected components include:

- formative practice: Short opportunities for students to try skills during learning.
- self-check opportunities: Built-in moments for students to reflect on their understanding.
- mastery checklist: A simple list of outcomes students can confirm they have met.
- extension challenge: A deeper task for students ready for more complexity.
- intervention support suggestions: Guidance for students who need scaffolded help.

Assessment expectations should support learning progression and differentiation.

## 12. Versioning

Lesson versions should progress in a clear and predictable way.

Recommended states include:

- Draft: The lesson is being created or revised.
- Review: The lesson is ready for editorial or instructional review.
- Approved: The lesson meets standards and is ready for publication.
- Published: The lesson is live for public use.

Semantic versioning should be used for lesson updates. Examples include:

- 1.0: Initial lesson version.
- 1.1: Minor content update or correction.
- 2.0: Major revision, structural change, or significant enhancement.

Version tracking helps preserve history and manage lesson improvement over time.

## 13. Publishing Principles

All production lessons should follow these publishing principles:

- Lesson content is independent from rendering.
- Rendering is independent from WordPress.
- Production lessons must not contain rendering logic.
- Lesson data must remain reusable by future platforms.

These principles protect the long-term flexibility, maintainability, and portability of the lesson content.
